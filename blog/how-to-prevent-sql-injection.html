How to Prevent SQL Injection

6 min read · Updated 2026

SQL injection is the single most common — and most dangerous — vulnerability in AI-generated code. The fix is always the same idea: never build a query by gluing in user input. Here is exactly how, in the three stacks most vibe-coded apps use.

Why it happens

When user input is concatenated into a query string, an attacker can send input that changes the query itself — reading, modifying or deleting your whole database. The fix is parameterized queries: you send the query and the data separately, so input can never become code.

PHP (mysqli / PDO)

Vulnerable$conn->query("SELECT * FROM users WHERE email='$email'");
Safe$stmt = $conn->prepare("SELECT * FROM users WHERE email = ?");
$stmt->bind_param("s", $email);
$stmt->execute();

Node.js (mysql2 / pg)

Vulnerabledb.query(`SELECT * FROM users WHERE email='${email}'`);
Safedb.query("SELECT * FROM users WHERE email = ?", [email]);

Python (sqlite3 / psycopg)

Vulnerablecur.execute("SELECT * FROM users WHERE email='%s'" % email)
Safecur.execute("SELECT * FROM users WHERE email = %s", (email,))

The rule

Put a placeholder (? or %s) where the value goes, and pass the value separately. Never use string concatenation, .format(), or f-strings to build a query. An ORM (Prisma, Eloquent, SQLAlchemy) does this for you — just avoid its raw-query escape hatches with user input.

Frequently asked questions

What is the best way to prevent SQL injection?

Use parameterized (prepared) queries: send the SQL and the user data separately with placeholders, so input can never be interpreted as query code. This is the single most effective defense.

Do ORMs prevent SQL injection?

Yes, for normal use — ORMs like Prisma, Eloquent and SQLAlchemy parameterize queries automatically. The exception is their raw-query methods, where you must still use parameters rather than string concatenation.

Is escaping input enough to stop SQL injection?

Manual escaping is error-prone and easy to get wrong. Parameterized queries are the reliable fix because the database treats the input strictly as data, not as part of the query.
