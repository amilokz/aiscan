Why the algorithm matters

Passwords should be stored with a slow hash built for the job — bcrypt or Argon2. Fast general-purpose hashes like MD5, SHA-1 and even SHA-256 can be brute-forced at billions of guesses per second, so a leaked database of them is effectively plaintext. AI-generated code very often reaches for md5() because it is short — which is exactly why this check exists.

FAQ

Is MD5 safe for passwords?

No. MD5 is a fast hash that modern hardware cracks at billions of attempts per second, and it has known collisions. Never use it for passwords — use bcrypt or Argon2.

What is the best way to hash passwords?

Use bcrypt (password_hash in PHP, the bcrypt library in Node) or Argon2id. They are deliberately slow and salted, which makes brute-forcing leaked hashes impractical.

Is SHA-256 good for passwords?

No. SHA-256 is excellent for integrity checks but too fast for password storage. Use a purpose-built password hash like bcrypt or Argon2 instead.
